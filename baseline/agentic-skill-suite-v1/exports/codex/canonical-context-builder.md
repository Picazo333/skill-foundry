# Canonical Context Builder

> Canonical skill definition. Adapters in `adapters/` are thin wrappers over
> this file — they may not change purpose, procedure, outputs, quality gates
> or stop conditions. See `/PORTABILITY.md` and `/shared/adapters/README.md`.

## Identity
- **ID:** `canonical-context-builder`
- **Category:** knowledge
- **Version:** `1.0.0`
- **Purpose:** Reconstruct and maintain the single canonical truth of a
  project — facts, locked decisions, current hypotheses, constraints,
  deprecated directions and open loops — from fragmented conversations,
  files, renames, decisions and prior outputs.

## Trigger
Use this skill when:
- A project has accumulated many chats, files, versions or renames and no
  single trustworthy source of truth exists.
- A clean handoff to a new agent/conversation/collaborator is needed.
- Current decisions must be separated from deprecated/rejected proposals.
- Canon must be updated after a completed phase, decision, or delivered
  artifact (`mode: UPDATE`).

## Non-trigger
Do not use this skill for:
- Generic summarization with no canonical-state requirement — just summarize
  directly, no artifact set needed.
- Researching facts outside the supplied sources — that is
  `research-architect`.
- Filling gaps with plausible-sounding guesses — if a fact is unknown, it
  goes in `OPEN_LOOPS.md`, never invented.
- Producing an implementation plan from the canon — that is `product-auditor`
  or `brand-skill-orchestrator`, which consume this skill's output.

## Context policy
- **REQUIRED_CONTEXT:** the project materials/artifacts to reconstruct canon
  from, and the objective of the build/update.
- **OPTIONAL_CONTEXT:** prior `PROJECT_CANON.md`, decision logs, changelogs,
  checkpoints, repo state.
- **DO_NOT_LOAD_BY_DEFAULT:** the full raw conversation history once a prior
  canon exists — read the canon plus the delta sources, not everything ever
  said. Unrelated projects' canon.

Prefer canonical artifacts over conversational memory.

## Inputs

### Minimum inputs
- Project materials, OR a current canonical artifact to update.
- The objective of the context build/update.

### Optional inputs
- Prior `PROJECT_CANON.md`
- Decision logs
- Changelogs
- Checkpoints
- Repo state

### RUN_REQUEST envelope
```yaml
RUN_REQUEST:
  objective:            # e.g. "rebuild canon from scratch" | "update canon after Phase 2"
  source_artifacts:      # list of files/chats/notes to reconstruct from
  known_context:         # anything already established, if not deriving from scratch
  constraints:           # e.g. "no external research", "brand-only scope"
  desired_output:        # full canon set | delta only | specific artifact
  mode: STANDARD          # STANDARD (rebuild) | UPDATE (delta against prior canon)
  prior_run:              # path to prior PROJECT_CANON.md / checkpoint, if mode: UPDATE
```

## Procedure
1. **Inventory sources.** List every source artifact; rank by likely
   authority and recency (a signed-off deliverable outranks a draft chat
   aside; a later timestamp outranks an earlier one for the same claim).
2. **Extract.** Pull out entities, renames, decisions, constraints,
   completed work, open loops and discarded/rejected directions from every
   source, tagging each extracted item with its source.
3. **Resolve conflicts.** Resolve only conflicts that the evidence actually
   resolves (e.g. a later authoritative source supersedes an earlier one).
   Every conflict that evidence does NOT resolve is preserved explicitly in
   `DECISION_REGISTER.md` / `OPEN_LOOPS.md` as unresolved — never silently
   picked.
4. **Build canonical sections.** Organize into: FACTS, LOCKED DECISIONS,
   CURRENT HYPOTHESES, CONSTRAINTS, DEPRECATED, OPEN LOOPS.
5. **Delta mode.** If `mode: UPDATE` and a prior canon exists, diff against
   it: only rewrite sections that actually changed; leave stable sections
   untouched and note in the delta what changed and why.
6. **Write the handoff.** Produce `NEXT_START_PROMPT.md`: a concise prompt
   that lets another agent continue accurately using only the canonical
   artifacts — never "re-read this conversation".
7. **Contradiction & staleness pass.** Re-scan the assembled canon once for
   internal contradictions (two LOCKED DECISIONS that conflict) and stale
   entries (a fact/decision superseded by a later one still marked current).
8. **Stop** when the next agent/human could pick up the project accurately
   using canon + referenced artifacts alone, with no unresolved
   contradiction left silently hidden.

### Checkpoints
For large reconstructions (many sources), checkpoint after step 2 (raw
extraction complete, before resolution) and after step 4 (sections built,
before delta/handoff), recording counts of items extracted/resolved/still
open so a resumed run doesn't re-extract from scratch.

## Outputs

### Required output artifacts
- `PROJECT_CANON.md` — the FACTS / LOCKED DECISIONS / CURRENT HYPOTHESES /
  CONSTRAINTS / DEPRECATED / OPEN LOOPS sections.
- `DECISION_REGISTER.md` — every decision, its status (locked/proposed/
  superseded), source, and date.
- `OPEN_LOOPS.md` — every unresolved question or unresolvable conflict,
  explicit and unhidden.
- `DEPRECATED_REGISTER.md` — rejected/superseded directions, with why they
  were dropped (prevents re-litigating settled discussions).
- `NEXT_START_PROMPT.md` — the handoff prompt for the next agent/session.

### RUN_RESULT envelope
```yaml
RUN_RESULT:
  status: COMPLETE            # COMPLETE | PARTIAL | BLOCKED
  summary:
  artifacts: [PROJECT_CANON.md, DECISION_REGISTER.md, OPEN_LOOPS.md, DEPRECATED_REGISTER.md, NEXT_START_PROMPT.md]
  decisions:                  # newly locked or newly resolved this run
  unresolved:                 # still-open contradictions/questions
  handoff:                    # recommended next skill + why
  quality:                    # gate results
```

## Handoffs
- → `research-architect` — when canon surfaces a material uncertainty that
  blocks a decision and needs exhaustive research architecture.
- → `product-auditor` — when canon is for an existing product/app and the
  next step is an audit/implementation plan.
- → `brand-discovery` — when canon is for a brand project entering/continuing
  the brand workflow.
- → `brand-skill-orchestrator` — when a multi-stage brand project needs
  routing after canon is refreshed.
- → `rapid-capture-triage` — when new raw/chaotic input needs structuring
  before it can be folded into canon.

## Failure modes
- **Inventing facts to fill gaps.** Detect: a canon entry has no traceable
  source. Fix: move it to `OPEN_LOOPS.md` as unknown, never state it as fact.
- **Silently picking a side in an unresolved conflict.** Detect: two sources
  disagree and neither is authoritative/more recent, but canon states one
  as settled. Fix: keep both, mark as `CURRENT HYPOTHESES` or log in
  `DECISION_REGISTER.md` as unresolved.
- **Rewriting stable canon on every update.** Detect: an UPDATE run changes
  sections with no new evidence behind the change. Fix: touch only what the
  new sources actually change; delta, don't regenerate.
- **Handoff that requires re-reading the whole conversation.** Detect:
  `NEXT_START_PROMPT.md` references "as discussed above" instead of a
  canonical artifact. Fix: rewrite so it's self-sufficient from artifacts
  alone.

## Quality gates
Must satisfy `/QUALITY_GATES.md` skill-level gates 1–10, plus:
- No deprecated decision appears as current in `PROJECT_CANON.md`.
- No unsupported fact is invented; every FACTS entry traces to a source.
- Every unresolved contradiction remains visible in `OPEN_LOOPS.md` or
  `DECISION_REGISTER.md` — none silently dropped.
- `NEXT_START_PROMPT.md` references canonical artifacts, not conversational
  memory.

## Stop conditions
- Normal completion: all five required artifacts produced, contradiction/
  staleness pass run, `status: COMPLETE`.
- Blocked: source artifacts are too sparse/contradictory to build even a
  minimal FACTS section → `status: BLOCKED`, state exactly what additional
  source material is needed.
- Never continue past producing a canon that presents an unresolved conflict
  as resolved.

# Codex adapter — Canonical Context Builder

## Invocation
Reference this skill from the repo's agent-instructions file (e.g.
`AGENTS.md`) as: "For canonical context work, read
`skills/01-canonical-context-builder/SKILL.md` and follow it exactly." The
coding agent loads `SKILL.md` on demand rather than keeping it permanently
in context.

## File I/O
Reads `source_artifacts` from the repo working tree (docs, commit history,
prior canon files). Writes the five required artifacts as real files in the
repo (default: repo root, or wherever the repo's convention places canonical
docs — check for an existing `PROJECT_CANON.md` location first).

## Environment constraints
Prefer `git log`/`git diff` and existing docs over asking the user to
re-paste history — the repo itself is the source-artifact inventory. Treat
files under version control as higher-authority than untracked scratch
notes, consistent with `references/authority-and-recency-ranking.md`.
