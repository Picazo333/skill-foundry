# Brand Quality Auditor

> Canonical skill definition. Adapters in `adapters/` are thin wrappers over
> this file — they may not change purpose, procedure, outputs, quality gates
> or stop conditions. See `/PORTABILITY.md` and `/shared/adapters/README.md`.

## Identity
- **ID:** `brand-quality-auditor`
- **Category:** brand
- **Version:** `1.0.0`
- **Purpose:** Audit a delivered creative/content artifact against explicit
  brand canon (strategy, verbal identity, visual identity) and produce a
  traceable PASS/FIX/POLISH/DEFER verdict per canon rule, a drift register,
  and a prioritized fix list — refusing to audit at all when canon is
  missing or incomplete.

## Trigger
Use this skill when:
- A delivered or in-progress brand output (web page, copy, deck, campaign,
  social creative, brand book itself) needs QA before/after ship.
- An implementation needs to be compared against approved canon to detect
  drift, regression, genericity or AI-slop.
- A gate in the brand workflow (post `creative-brief-generator`, post
  `brand-content-system`) requires a pass/fail check before the artifact
  proceeds.

## Non-trigger
Do not use this skill for:
- Creating brand canon when none exists — that is `brand-strategy`,
  `brand-verbal-identity`, `brand-visual-direction`, or `brand-book-builder`.
- Subjective aesthetic critique with no stated criteria ("I just don't like
  it") — this skill audits against canon, not taste. If canon doesn't cover
  the objection, it is out of scope (see Failure modes).
- Replacing or reopening approved upstream strategy — a finding that
  strategy itself seems wrong is escalated, not resolved here (see
  Handoffs).

## Context policy
- **REQUIRED_CONTEXT:** the artifact to audit, and the brand canon sections
  that apply to it (strategy/positioning, verbal identity, visual identity —
  whichever are relevant to the artifact's type). Canon must be explicit,
  approved material (`brand-book-builder` output or equivalent locked
  canon), never inferred.
- **OPTIONAL_CONTEXT:** the specific audit objective, target channel, prior
  audit/`DRIFT_REGISTER.md`, known/pre-approved exceptions to canon.
- **DO_NOT_LOAD_BY_DEFAULT:** unrelated brands' canon; the full conversation
  history that produced the artifact (use the artifact itself); canon
  sections that don't apply to this artifact's type (e.g. motion/UI rules
  for a static print piece) — load only what's relevant per procedure step 1.

Prefer canonical artifacts over conversational memory (`/ARCHITECTURE.md`).

## Inputs

### Minimum inputs
- The artifact to audit (file, URL, pasted content, or described asset).
- Brand canon covering at least one of: strategy/positioning, verbal
  identity, visual identity — enough to check the artifact's actual claims
  against something explicit and approved.

### Optional inputs
- Specific objective (e.g. "check for regression against last quarter's
  campaign" vs. "full audit before launch").
- Target channel (changes usability/fitness checks in step 5).
- Prior audit / `DRIFT_REGISTER.md` (enables delta-mode auditing).
- Known exceptions (pre-approved, documented deviations from canon that
  must not be re-flagged).

### RUN_REQUEST envelope
```yaml
RUN_REQUEST:
  objective:            # e.g. "pre-launch QA" | "drift check vs. Q1 canon" | "self-audit brand book"
  source_artifacts:      # the artifact(s) to audit + the canon artifact(s) to audit against
  known_context:         # channel, audience, campaign, known exceptions
  constraints:           # e.g. "verbal only, visual QA out of scope this run"
  desired_output:        # full_audit | delta_only | specific_artifact
  mode: STANDARD          # STANDARD | AUDIT | UPDATE (delta vs. prior audit)
  prior_run:              # path to prior DRIFT_REGISTER.md / BRAND_QA_REPORT.md, if mode: UPDATE
```

## Procedure
1. **Canon gate.** Before doing any comparison, confirm canon actually
   exists and is explicit for the dimensions relevant to this artifact
   (e.g. a web page needs at minimum verbal + visual canon; a positioning
   claim needs strategy canon). If required canon is missing, unlabeled as
   approved, or too vague to check specific claims against (e.g. "sound
   modern" with no defined voice attributes) — **stop and return
   `status: BLOCKED`** per Stop conditions. Do not proceed to grade against
   assumed or inferred standards.
2. **Load only relevant canon.** From the confirmed canon, load only the
   sections that apply to this artifact's type and the requested scope
   (per `constraints`). Do not load unrelated canon sections.
3. **Strategic alignment.** Check the artifact's audience framing,
   positioning, core promise, and any factual/competitive claims against
   canon's strategy section. Flag anything asserted that canon does not
   support or that contradicts it.
4. **Verbal alignment.** Check voice/tone, vocabulary (approved/banned
   terms), and message hierarchy (what's said first/loudest) against the
   verbal identity canon.
5. **Visual alignment.** Check composition, typography, color roles (not
   just "on-palette" but used in its canonical role), imagery treatment,
   and UI/motion conventions where relevant, against the visual identity
   canon.
6. **Objective/channel fitness.** Check the artifact actually works for its
   stated objective and channel (e.g. CTA present and canon-compliant for a
   conversion page; legibility/contrast for the delivery surface). This is
   usability against the stated objective, not new aesthetic preference.
7. **AI-slop and genericity detection.** Run the artifact against
   `references/ai-slop-checklist.md`: generic filler adjectives, hedge-y
   copy patterns, gradient-blob/stock-abstract visual cliches,
   over-decoration with no message function, and interchangeable-with-any-
   brand phrasing. Every hit must be tied to a specific canon rule it
   violates (e.g. "violates verbal canon's banned-words list" or "violates
   visual canon's decoration-has-function rule") — a hit with no traceable
   canon rule is logged as an observation, not a finding (see Quality
   gates).
8. **Classify every checked item.** For each canon rule checked, classify
   the artifact against it as one of:
   - `PASS` — complies.
   - `FIX` — canon violation that blocks approval; must be corrected before
     ship.
   - `POLISH` — canon-compliant but weak execution; non-blocking
     improvement.
   - `DEFER` — a real issue, but resolving it requires an upstream decision
     (canon itself is ambiguous/silent, or the fix implies a strategy
     change) — escalate, don't decide unilaterally.
9. **Separate canon violation from subjective preference.** Anything that
   is a reviewer preference and not traceable to a canon rule is excluded
   from `FIX`/`POLISH` classification entirely and, if worth surfacing, is
   listed separately as an out-of-scope observation — never mixed into the
   graded findings.
10. **Delta mode.** If `mode: UPDATE` and a prior `DRIFT_REGISTER.md`
    exists, diff against it: distinguish newly introduced drift from
    already-known/accepted drift, and note regressions (previously PASS,
    now FIX).
11. **Build the fix list.** From all `FIX` items, produce the smallest set
    of changes that restores canon compliance — no scope creep into
    `POLISH` items or unrelated redesign.
12. **Stop** when every canon rule loaded in step 2 has been checked and
    classified, every finding traces to a specific canon rule, and the fix
    list contains only what's required to reach compliance.

### Checkpoints
For audits spanning many artifact pieces (e.g. a full campaign or brand
book self-audit), checkpoint after step 2 (canon confirmed + scoped) and
after step 8 (all items classified, before fix-list assembly), recording
counts of rules checked / PASS / FIX / POLISH / DEFER so a resumed run
doesn't re-check already-classified items.

## Outputs

### Required output artifacts
- `BRAND_QA_REPORT.md` — every canon rule checked, its classification
  (PASS/FIX/POLISH/DEFER), and the citation to the specific canon rule.
- `FIX_LIST.md` — the smallest prioritized set of required changes (FIX
  items only, ordered by severity/blocking status).
- `DRIFT_REGISTER.md` — drift and regression tracked over time: what
  changed since the prior audit (if any), what's newly introduced vs.
  already-known, and AI-slop/genericity findings with their canon citation.

### RUN_RESULT envelope
```yaml
RUN_RESULT:
  status:      # COMPLETE | PARTIAL | BLOCKED
  summary:
  artifacts: [BRAND_QA_REPORT.md, FIX_LIST.md, DRIFT_REGISTER.md]
  decisions:   # classifications locked this run
  unresolved:  # DEFER items needing upstream decision; missing-canon gaps
  handoff:
  quality:
```

## Handoffs
- → `brand-book-builder` — when the audit surfaces that canon itself is
  ambiguous, silent, or contradictory on a point needed to classify a
  finding (a `DEFER` item requiring canon clarification, not a new audit
  decision).
- → `creative-brief-generator` — when `FIX_LIST.md` implies the artifact
  needs to be rebriefed/reworked rather than spot-fixed.
- → `product-auditor` — when the artifact under audit is a product/app
  surface and findings implicate product behavior beyond brand
  presentation.

## Failure modes
- **Grading against assumed/implicit taste.** Detect: a finding cites no
  specific canon rule, only "feels off"/"doesn't feel premium". Fix: do not
  classify it as `FIX`/`POLISH` at all — canon gate (step 1) should have
  caught missing canon; if canon exists but doesn't cover this dimension,
  log as an out-of-scope observation, not a finding.
- **Auditing with incomplete canon and quietly filling gaps.** Detect: the
  artifact has visual elements but only verbal canon was supplied, and the
  run proceeds to grade visuals anyway. Fix: scope the audit to only the
  canon dimensions actually supplied; if the requested objective requires a
  missing dimension, return `BLOCKED` for that dimension specifically
  rather than improvising a visual standard.
- **Reopening strategy under the guise of an audit finding.** Detect: a
  `FIX` item actually argues the brand's positioning/promise itself is
  wrong, not that the artifact fails to reflect it. Fix: reclassify as
  `DEFER` and hand off to the owning upstream skill instead of asserting a
  new strategic direction.
- **AI-slop findings with no canon traceability.** Detect: a genericity
  finding lists a checklist hit (e.g. "gradient blob") without naming the
  canon rule it breaks. Fix: every AI-slop hit must cite the specific
  canon rule (visual decoration-has-function rule, verbal banned-phrase
  list, etc.) — see `references/ai-slop-checklist.md`.
- **Fix list scope creep.** Detect: `FIX_LIST.md` includes `POLISH` items
  or redesign suggestions beyond restoring compliance. Fix: strip to the
  smallest set that clears all `FIX` classifications.

## Quality gates
Must satisfy `/QUALITY_GATES.md` skill-level gates 1–10, plus:
- **Requires explicit canon** (`/QUALITY_GATES.md` suite-level gate 8):
  every run either has explicit, approved canon for the dimensions it
  grades, or returns `BLOCKED` for the ungraded dimensions — never grades
  against inferred/implicit standards.
- Every `FIX`/`POLISH`/`DEFER` finding traces to a specific canon rule
  citation, not a general aesthetic judgment.
- No aesthetic fiat: reviewer preference not backed by canon is excluded
  from graded findings.
- `FIX_LIST.md` is prioritized and contains only what's needed to restore
  compliance.
- Approved strategy is never casually reopened inside an audit; a
  strategy-level objection is always routed to `DEFER` + handoff.
- AI-slop detection is operationalized with concrete examples
  (`references/ai-slop-checklist.md`), not a vague "avoid AI-sounding
  content" instruction.

## Stop conditions
- Normal completion: canon gate passed, all applicable canon rules checked
  and classified, all three required artifacts produced,
  `status: COMPLETE`.
- Blocked (insufficient input): canon for a requested dimension is
  missing, unapproved, or too vague to check specific claims against →
  `status: BLOCKED`, state exactly which canon (which dimension, which
  artifact) is needed before an audit can run. This applies even if the
  artifact itself is fully available — a fully-formed artifact with no
  canon to compare it to still returns `BLOCKED`.
- Never continue past: producing a `FIX`/`POLISH` classification with no
  canon rule citation; presenting a strategic disagreement as an audit
  finding; treating a partial-canon run as a full audit without noting the
  ungraded dimensions.

# Codex adapter — Brand Quality Auditor

## Invocation
Reference this skill from the repo's agent-instructions file (e.g.
`AGENTS.md`) as: "For brand QA on creative/content artifacts, read
`skills/14-brand-quality-auditor/SKILL.md` and follow it exactly,
including the canon gate — do not audit without locating explicit,
approved canon in the repo first." The coding agent loads `SKILL.md` on
demand rather than keeping it permanently in context.

## File I/O
Reads the artifact under audit and canon (brand book, verbal/visual
identity docs) from the repo working tree — typically under a
`brand/` or `canon/` directory, or wherever `brand-book-builder`'s output
lives in this repo. If no such canon directory/files exist or are found
empty, this is treated exactly as canon-not-supplied: return `BLOCKED`
rather than falling back to generic web/copy conventions. Writes the
three required artifacts as real files in the repo (default: alongside
the artifact under audit, or an `audits/` directory per repo convention).

## Environment constraints
Prefer canon files under version control (higher authority) over any
inline comments or commit messages describing "what the brand should feel
like" — the latter is not approved canon and must not substitute for it.
