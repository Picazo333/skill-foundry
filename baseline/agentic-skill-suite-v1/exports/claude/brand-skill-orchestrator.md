# Brand Skill Orchestrator

> Canonical skill definition. Adapters in `adapters/` are thin wrappers over
> this file — they may not change purpose, procedure, outputs, quality gates
> or stop conditions. See `/PORTABILITY.md` and `/shared/adapters/README.md`.
>
> This skill routes the other 14 skills in this suite. It never does their
> work itself. Its own contract is built directly against their real,
> finished `manifest.json` files (not imagined artifact names) — see
> `references/routed-skill-contracts.md` for the exact mapping this
> procedure depends on.

## Identity
- **ID:** `brand-skill-orchestrator`
- **Category:** brand-orchestration
- **Version:** `1.0.0`
- **Purpose:** Route a multi-stage brand project through only the necessary
  skills, in the correct order, using existing artifacts and approvals —
  preventing restarts, duplicated work, and manual coordination.

## Trigger
Use this skill when:
- A brand project spans multiple stages (discovery through content/QA) and
  needs coordinated routing rather than manual skill-by-skill invocation.
- An existing partial brand system needs to continue from wherever it left
  off, without redoing finished stages.
- Multiple people/agents/tools are collaborating on one brand project and
  need a single source of truth for "what's next."

## Non-trigger
Do not use this skill for:
- Doing deep brand strategy, verbal, visual, identity, book, brief, content
  or QA work itself — always dispatch to the owning skill.
- A single-skill request with no multi-stage coordination need (just invoke
  that skill directly).
- Forcing every project through every stage regardless of what the
  objective actually requires (e.g. a content-only engagement on an
  already-approved brand should not be routed through Discovery again).

## Context policy
- **REQUIRED_CONTEXT:** the brand project objective, and an inventory of
  which of the 14 skills' output artifacts already exist for this project
  (even if empty — "nothing exists yet" is valid input for a from-zero run).
- **OPTIONAL_CONTEXT:** `PROJECT_CANON.md` (from `canonical-context-builder`),
  explicit approval states per artifact, tool/capacity availability (for
  `ai-resource-router` invocations), deadlines.
- **DO_NOT_LOAD_BY_DEFAULT:** the full content of every downstream skill's
  artifacts — this skill reads artifact *existence, version and approval
  state*, not full content, unless resolving a specific conflict requires it.

## Inputs

### Minimum inputs
- Brand project objective.
- Available artifacts (list of what exists, with paths/versions if known).

### Optional inputs
- `PROJECT_CANON.md`
- Approval states per artifact (approved / pending / rejected)
- Tool/capacity availability
- Deadlines

### RUN_REQUEST envelope
```yaml
RUN_REQUEST:
  objective:              # e.g. "get brand project X to a published brand book" | "content-only engagement, brand already approved"
  source_artifacts:        # known existing artifacts, with paths and approval state if known
  known_context:
  constraints:
  desired_output: workflow_state_and_next_run   # or: full_completion_report
  mode: STANDARD            # STANDARD | RESUME
  prior_run:                # path to prior BRAND_WORKFLOW_STATE.md, if resuming
```

## Procedure
1. **Inventory.** List every brand-suite artifact that exists for this
   project (see `references/routed-skill-contracts.md` for the full
   artifact→owning-skill map). For each: exists / missing, version/date if
   known, approval state if known.
2. **Determine current stage.** Apply the stage rules in
   `references/stage-detection-rules.md` (discovery → strategy → verbal+visual
   → identity system → brand book → creative brief / content system → QA) to
   the inventory. Detect: completed stages, an in-progress stage, conflicting
   artifacts (e.g. two versions of `BRAND_STRATEGY.md` with no clear
   authoritative one), and stages skipped because the objective doesn't need
   them (e.g. a content-only engagement never needs `brand-visual-direction`
   if visual identity already exists and isn't in scope).
3. **Discovery gate.** Route to `brand-discovery` ONLY if `BRAND_STRATEGY.md`
   is missing/blocked AND `BRAND_DISCOVERY_BRIEF.md` is missing or has
   material `DISCOVERY_GAPS.md` that block strategy. Do not re-run discovery
   because it is merely old.
4. **Research gate.** Route to `research-architect` ONLY when market/
   category/customer uncertainty materially blocks `brand-strategy` (e.g.
   `DISCOVERY_GAPS.md` names an unresolved market question) — never as a
   default step.
5. **Strategy → Verbal/Visual fan-out.** Once `BRAND_STRATEGY.md` (with
   locked positioning) exists, route to whichever of `brand-verbal-identity`
   and `brand-visual-direction` are missing/incomplete for this objective.
   These may run in parallel — they do not depend on each other.
6. **Identity System gate.** Route to `brand-identity-system` once
   `APPROVED_VISUAL_DIRECTION.md` exists and `IDENTITY_SYSTEM.md` does not
   (or is stale against a newer approved direction).
7. **Brand Book gate.** Route to `brand-book-builder` once both the verbal
   artifact set (`VERBAL_IDENTITY.md`, `MESSAGE_HIERARCHY.md`,
   `VOICE_EXAMPLES.md`) and the identity-system artifact set
   (`IDENTITY_SYSTEM.md`, `DESIGN_TOKENS.json`, `APPLICATION_RULES.md`) exist.
   If `brand-book-builder` returns `status: PARTIAL` with a coherence gap,
   route back to whichever upstream skill(s) it names — never route forward
   to production skills on a `PARTIAL` book without surfacing that to the
   requester first.
8. **Production routing.** Once `BRAND_BOOK.md` exists (or the objective
   only needs the specific canon layers a deliverable requires — see
   `creative-brief-generator`'s and `brand-content-system`'s own minimum
   inputs, which can be satisfied by canon short of a full compiled book):
   route one-off deliverable requests to `creative-brief-generator`, and
   recurring/systemic content programs to `brand-content-system`.
9. **Quality gate invocation.** Route to `brand-quality-auditor` at
   meaningful gates — after a production skill delivers a completed artifact
   set, or before a milestone is presented externally — not after every
   trivial action. Never audit against canon the auditor would itself flag
   as missing/unapproved (check `brand-quality-auditor`'s own `BLOCKED`
   stop condition before routing to it).
10. **Resource routing.** Invoke `ai-resource-router` when the execution
    environment or model/tool allocation for a routed skill's run materially
    matters (cost, quota, latency) — it produces a dispatch prompt, it does
    not replace this skill's routing decision.
11. **Update workflow state.** Write/update `BRAND_WORKFLOW_STATE.md` and
    `NEXT_SKILL_RUN.json` after every routing decision. Package the handoff
    for the chosen next skill in `HANDOFF_PACKAGES/<skill-id>/` — canonical
    artifacts + decisions + unresolved items + constraints, per
    `ARCHITECTURE.md`'s handoff rule, never "read the whole project."
12. **Stop.** When the stated objective is fulfilled (not when every
    possible stage has run), write `COMPLETION_REPORT.md` summarizing what
    ran, what was skipped and why, and what remains open.

### Checkpoints
Checkpoint (update `BRAND_WORKFLOW_STATE.md`) after every routing decision,
not just at the end — a resumed run must be able to pick up from the last
decision without re-inventorying from scratch, per `RESUME` mode below.

## Outputs

### Required output artifacts
- `BRAND_WORKFLOW_STATE.md` — full stage inventory, current stage, decisions
  made, decisions pending.
- `NEXT_SKILL_RUN.json` — the single next skill to invoke and its
  `RUN_REQUEST`, ready to dispatch.
- `HANDOFF_PACKAGES/` — one folder per routed skill, containing exactly the
  canonical artifacts + decisions + constraints that skill needs.
- `COMPLETION_REPORT.md` — produced when the objective is fulfilled (may be
  absent on intermediate runs where `RUN_RESULT.status` is `PARTIAL`,
  meaning more routing remains).

### RUN_RESULT envelope
```yaml
RUN_RESULT:
  status: COMPLETE            # COMPLETE (objective fulfilled) | PARTIAL (more routing remains) | BLOCKED
  summary:
  artifacts: [BRAND_WORKFLOW_STATE.md, NEXT_SKILL_RUN.json, HANDOFF_PACKAGES/, COMPLETION_REPORT.md]
  decisions:                  # stage/routing decisions made this run
  unresolved:                 # conflicts/gaps that block further routing
  handoff:                    # the next skill to run, or "objective complete"
  quality:
```

### Output schema
See `schemas/output.schema.json`.

## Handoffs
- → any of the 14 owned skills, per the stage rules above.
- → `research-architect` — conditional, per step 4.
- → `ai-resource-router` — conditional, per step 10.
- → `canonical-context-builder` — when the project's cross-cutting canon
  (not brand-specific) needs to be rebuilt/updated before brand routing can
  proceed reliably.

## Failure modes
- **Doing the routed skill's work itself.** Detect: `BRAND_WORKFLOW_STATE.md`
  contains actual strategy/verbal/visual/content decisions instead of a
  routing decision. Fix: strip domain content, route to the owning skill
  instead.
- **Re-running a completed stage without cause.** Detect: a stage's required
  artifacts exist and are approved, but the stage is routed to again with no
  new evidence/objective change. Fix: skip it; only re-run on an explicit
  update objective or a detected conflict.
- **Forcing every project through every stage.** Detect: a narrow objective
  (e.g. "just need a QA pass on this one asset") gets routed through
  discovery/strategy/etc. Fix: route directly to the skill(s) the objective
  actually needs, per step 2's stage detection against the *stated
  objective*, not a fixed checklist.
- **Routing forward on a `PARTIAL`/`BLOCKED` upstream result.** Detect:
  `brand-book-builder` or `brand-quality-auditor` returned `PARTIAL`/
  `BLOCKED` and the orchestrator routed to the next production skill anyway.
  Fix: surface the gap, route back to the named upstream skill(s) first.

## Quality gates
Must satisfy `/QUALITY_GATES.md` skill-level gates 1–10, plus:
- Never reruns a completed stage without cause.
- Never substitutes orchestration for domain work.
- Uses artifact versions/approval states, not assumptions.
- Approval gates are explicit in `BRAND_WORKFLOW_STATE.md`.
- Partial projects resume cleanly from `BRAND_WORKFLOW_STATE.md` alone.
- No circular orchestration loop (a skill routed to twice in one run without
  a new artifact/decision between the two routings is a bug, not a retry).

## Stop conditions
- Normal completion: stated objective fulfilled, `COMPLETION_REPORT.md`
  written, `status: COMPLETE`.
- Partial: more routing remains after this run's single next-skill
  recommendation — `status: PARTIAL`, `NEXT_SKILL_RUN.json` populated.
- Blocked: a conflict exists that no available skill can resolve without a
  human decision (e.g. two equally-authoritative, contradictory
  `BRAND_STRATEGY.md` versions) — `status: BLOCKED`, state exactly what
  decision is needed and from whom.
- Never route forward past an unresolved coherence gap or a stage the
  auditor would flag as missing canon.

# Claude adapter — Brand Skill Orchestrator

## Invocation
Native Claude Skill. In an agentic environment (Claude Code / Claude
agents), this skill can actually invoke the routed skill's own SKILL.md as
a sub-task/sub-agent call after producing `NEXT_SKILL_RUN.json` — closing
the loop within one session rather than requiring manual hand-carry between
sessions, when the harness supports it.

Native registration (auto-triggering and invocation by name) depends on the
`name`/`description` YAML frontmatter at the top of `SKILL.md`; without it the
skill can still be run by loading `SKILL.md` directly.

## File I/O
- **Agentic environments:** reads the suite's `skills/*/` output directories
  directly from the working tree to build the artifact inventory, writes
  `BRAND_WORKFLOW_STATE.md`/`NEXT_SKILL_RUN.json`/`HANDOFF_PACKAGES/`/
  `COMPLETION_REPORT.md` as real files (default: a `runs/<project>/` dir the
  user specifies, kept separate from the suite's own `skills/` source tree).
- **claude.ai (no filesystem):** falls back to `adapters/generic.md`'s
  upload/paste pattern.

## Environment constraints
Per `/shared/policies/AUTONOMY.md`: once given a clear objective and
artifact inventory, proceed through routing decisions without asking
"should I continue" at each stage transition — only stop per `SKILL.md`'s
own stop conditions (objective fulfilled, or a genuine `BLOCKED` conflict).

## Fallback
In a surface without a native Skill primitive (e.g. claude.ai without
filesystem access, or a harness that does not parse `SKILL.md` frontmatter),
load `SKILL.md` as a plain instruction document and follow
`adapters/generic.md` for artifact input/output. This skill additionally
supports an optional sub-agent auto-dispatch extension when the harness
supports it, independent of this fallback.
