# Rapid Capture & Triage

> Canonical skill definition. Adapters in `adapters/` are thin wrappers over
> this file — they may not change purpose, procedure, outputs, quality gates
> or stop conditions. See `/PORTABILITY.md` and `/shared/adapters/README.md`.

## Identity
- **ID:** `rapid-capture-triage`
- **Category:** operations
- **Version:** `1.0.0`
- **Purpose:** Turn fast, chaotic raw capture (voice-note transcript,
  dictation, fragmented text notes) into a structured preview and machine
  delta against an operational system (projects/processes/tasks/backlog),
  while preserving every genuine ambiguity the input actually contains and
  doing the least formatting work necessary.

## Trigger
Use this skill when:
- The user dictates or dumps many updates quickly (voice-note transcript,
  stream-of-consciousness text, a pile of short fragments).
- Task/project priorities need reconciling from natural language against a
  known snapshot.
- A preview is needed before writing to a JSON/PM-tool update.
- Notes-app-speed capture must become structured input for another system,
  without the user hand-formatting it first.

## Non-trigger
Do not use this skill for:
- Long-term canonical synthesis across historical files/decisions — that is
  `canonical-context-builder`.
- Executing the captured tasks — this skill only structures the capture; it
  never performs the work items it triages.
- Inventing a priority, project assignment, owner, or due date the input
  does not state or clearly imply — if it's not in the capture, it goes to
  `AMBIGUITIES.md`, never guessed.
- Auditing an existing product/process for quality — that is
  `product-auditor`.

## Context policy
- **REQUIRED_CONTEXT:** the raw capture itself (transcript/text), and the
  objective (what target system/shape the structured output should match).
- **OPTIONAL_CONTEXT:** current task/project snapshot (to match against for
  duplicates/renames/moves), a category taxonomy if the target system uses
  non-default categories, an existing JSON state to patch, canonical context
  (`PROJECT_CANON.md` from `canonical-context-builder`) for entity names.
- **DO_NOT_LOAD_BY_DEFAULT:** full historical conversation/chat logs beyond
  the raw capture itself; unrelated projects' snapshots; the target system's
  full history/audit log (only its current snapshot is needed to diff
  against).

Prefer canonical artifacts and the current snapshot over conversational
memory (`ARCHITECTURE.md`).

## Inputs

### Minimum inputs
- Raw capture (transcript, dictation, fragmented notes).

### Optional inputs
- Current task/project snapshot.
- Category taxonomy (if not using the default set below).
- Existing JSON state to patch (`mode: UPDATE`).
- Canonical context (e.g. `PROJECT_CANON.md`).

### RUN_REQUEST envelope
```yaml
RUN_REQUEST:
  objective:            # e.g. "triage this morning's voice memo into the backlog"
  source_artifacts:      # the raw capture, plus optional snapshot/taxonomy/JSON
  known_context:         # canonical context, prior decisions, if any
  constraints:           # e.g. "do not touch project X", "task-only, no new projects"
  desired_output:        # preview_and_delta | preview_only | delta_only
  mode: STANDARD          # QUICK (single-pass, no snapshot matching) | STANDARD (full match against snapshot) | UPDATE (patch supplied JSON)
  prior_run:              # path to existing JSON/snapshot, required when mode: UPDATE
```

## Procedure
1. **Segment.** Split the raw capture into atomic changes — one fragment per
   distinct intent/update. Keep each fragment's original wording verbatim
   alongside its segment; never paraphrase before classifying (paraphrasing
   before classification is how ambiguity quietly gets flattened).
2. **Classify each fragment twice:**
   - **Target type:** `project | process | task | recurrent | supervision |
     doubt | idea | backlog | remove | rename | move | preserve`. See
     `references/classification-taxonomy.md` — pay particular attention to
     the recurrent-vs-supervision distinction (a named quality gate).
   - **Epistemic status:** `fact | hypothesis | action-item |
     genuinely-ambiguous`. See
     `references/fragment-epistemic-status-urgency.md`. A fragment stays
     `genuinely-ambiguous` if classification would require inventing
     information the fragment doesn't contain — do not force it into a
     cleaner category to make the output tidier.
3. **Detect priority/time signals.** Scan each fragment for explicit
   priority or urgency language and explicit or relative time signals ("today",
   "before Thursday", "after the launch"). Preserve the *relative order*
   fragments were spoken/written in when no explicit priority is given — do
   not infer a priority ranking from silence.
4. **Match against the snapshot** (if `mode: STANDARD` or `UPDATE` and a
   snapshot/JSON was supplied). For each fragment naming an item, look for:
   - an existing item with the same or near-identical name (possible
     duplicate),
   - an existing item explicitly renamed/moved/removed by the fragment,
   - no match (new item).
   A near-match is not an automatic match — if identity is unclear (e.g. two
   plausible existing items), record it as an ambiguity rather than picking
   one.
5. **Apply only explicit changes.** Every field not mentioned in a fragment
   stays exactly as it was in the snapshot. Never delete, rename, or
   reprioritize an existing item the capture didn't mention.
6. **Surface true ambiguities compactly.** Collect every fragment left
   `genuinely-ambiguous` in step 2, every unresolved match from step 4, and
   every contradiction between two fragments in the same capture (e.g. "kill
   the onboarding project" ... later "add a task to the onboarding project")
   into `AMBIGUITIES.md`. Compact means one entry per ambiguity with the
   verbatim fragment(s) and the specific question that needs a human answer
   — not a wall of caveats, and not silence either. Ambiguity in the input
   must never become invented certainty in the output, and it must never be
   dropped to make the preview look cleaner.
7. **Build the human preview.** Group everything else (successfully
   classified, non-ambiguous fragments) into `CAPTURE_PREVIEW.md`, grouped
   exactly the way the target system expects (by target type, then by
   project/parent if the snapshot provides one). Every preview line traces
   back to its source fragment.
8. **Internal-consistency check, then emit the machine delta.** Before
   writing `STRUCTURED_DELTA.json`, verify: every operation in the intended
   delta has a corresponding line in `CAPTURE_PREVIEW.md`, no operation
   touches an item that has an unresolved entry in `AMBIGUITIES.md`, and no
   operation silently deletes/overwrites an unmentioned field. If the check
   fails, fix the preview/ambiguity set first — never emit a delta that
   disagrees with the preview a human is expected to have reviewed.
9. **Write `APPLY_INSTRUCTIONS.md`.** Concrete, ordered steps for applying
   `STRUCTURED_DELTA.json` to the real target system (or for a human to
   apply it manually), including what to do about anything left in
   `AMBIGUITIES.md` (apply everything else now, hold the ambiguous items) and
   how to re-run this skill once those are resolved.

### Checkpoints
For a very long capture (many dozens of fragments), checkpoint after step 2
(all fragments segmented and dual-classified, before snapshot matching),
recording per-fragment: original text, target type, epistemic status. A
resumed run skips re-segmentation and re-classification and starts at step 4.

## Outputs

### Required output artifacts
- `CAPTURE_PREVIEW.md` — human-readable preview, grouped as the target
  system expects, every line traceable to a source fragment.
- `STRUCTURED_DELTA.json` — the machine-applicable patch; must match the
  preview exactly (step 8).
- `AMBIGUITIES.md` — every fragment/match/contradiction that could not be
  resolved without inventing information, with the verbatim fragment and the
  specific question a human needs to answer.
- `APPLY_INSTRUCTIONS.md` — concrete steps to apply the delta and to handle
  the held-back ambiguous items.

### RUN_RESULT envelope
```yaml
RUN_RESULT:
  status:      # COMPLETE | PARTIAL | BLOCKED
  summary:
  artifacts: [CAPTURE_PREVIEW.md, STRUCTURED_DELTA.json, AMBIGUITIES.md, APPLY_INSTRUCTIONS.md]
  decisions:   # explicit changes applied this run (renames/moves/removes actually captured)
  unresolved:  # every entry also in AMBIGUITIES.md
  handoff:
  quality:
```

### Output schema
See `schemas/output.schema.json` for the machine-checkable shape of the
artifact set / `RUN_RESULT`.

## Handoffs
- → `canonical-context-builder` — pass `CAPTURE_PREVIEW.md` and
  `STRUCTURED_DELTA.json` as `source_artifacts` (`objective: "fold new
  captured updates into canon"`) when the capture affects project-level
  facts/decisions rather than only task-level items. This is the default
  next step per `WORKFLOW_MAP.md`.
- → `ai-resource-router` — when the resolved delta implies dispatching
  specific tasks to a specific model/tool.
- → `product-auditor` — when a captured fragment describes a product/process
  defect rather than a task ("the login flow breaks on X") and needs audit
  rather than triage.

Pass canonical artifacts (the four outputs above), not the raw capture or
conversation — the next skill/agent should never need "re-read the voice
memo."

## Failure modes
- **Flattening ambiguity into false structure.** Detect: every fragment
  ended up classified with high confidence, none in `AMBIGUITIES.md`, on an
  input that was actually messy/contradictory. Fix: re-run step 2/6 — messy
  input producing zero ambiguities is a signal the classification was
  forced, not resolved.
- **Silent deletion of unmentioned items.** Detect: an item present in the
  snapshot is missing from the resulting state with no corresponding
  `remove` fragment. Fix: restore it; only an explicit `remove` fragment may
  drop an item.
- **Conflating recurrent and supervision.** Detect: a fragment about an
  ongoing check-in/monitoring duty ("keep an eye on X weekly") gets typed as
  `recurrent` (a repeating task) instead of `supervision` (an oversight
  responsibility with no fixed completion), or vice versa. Fix: re-classify
  per `references/classification-taxonomy.md`.
- **Delta/preview drift.** Detect: `STRUCTURED_DELTA.json` contains an
  operation with no matching line in `CAPTURE_PREVIEW.md`, or vice versa.
  Fix: do not emit the delta; resolve the mismatch first (step 8).
- **Priority invented from silence.** Detect: an output ordering implies
  urgency/priority the capture never stated. Fix: fall back to capture
  order; note in `AMBIGUITIES.md` if a priority call is actually needed
  downstream.
- **Duplicate detection skipped.** Detect: a new item is created that is
  really a rename/restatement of an existing snapshot item. Fix: run step 4
  before finalizing the preview; when identity is genuinely unclear, log the
  ambiguity rather than guessing either way.

## Quality gates
Must satisfy `/QUALITY_GATES.md` skill-level gates 1–10, plus (skill-level,
and this skill is also named directly in the suite-level gate "Rapid Capture
preserves real ambiguity"):
- No silent deletion of an unmentioned item.
- Recurrent vs. supervision are never conflated (step 2 / classification
  taxonomy applied).
- Duplicate detection is actually performed whenever a snapshot is supplied.
- `STRUCTURED_DELTA.json` matches `CAPTURE_PREVIEW.md` exactly — no
  operation in one without a corresponding line in the other.
- Every genuine ambiguity in the source capture survives into
  `AMBIGUITIES.md` — none silently resolved, none dropped.

## Stop conditions
- Normal completion: all four required artifacts produced, the step 8
  consistency check passes, `status: COMPLETE`.
- Partial: the capture is usable but part of it could not be classified even
  as `genuinely-ambiguous` with the given context (e.g. a fragment referring
  to a snapshot that wasn't supplied) → `status: PARTIAL`, state exactly what
  additional input (snapshot, taxonomy) would unblock it.
- Blocked: no raw capture supplied, or the capture is empty/unusable (e.g.
  garbled transcript with no recoverable fragments) → `status: BLOCKED`.
- Never continue past emitting a delta that disagrees with its own preview,
  and never continue past presenting a genuinely ambiguous fragment as a
  confidently classified one.

# Claude adapter — Rapid Capture & Triage

## Invocation
Runs as a native Claude Skill: this directory (`SKILL.md` + `schemas/` +
`templates/` + `references/`) is loaded when invoked by name or
auto-triggered by the `Trigger` conditions in `SKILL.md`. In Claude Code,
this is commonly triggered right after a voice-dictated or pasted note is
dropped into the conversation with an instruction like "triage this."

Native registration (auto-triggering and invocation by name) depends on the
`name`/`description` YAML frontmatter at the top of `SKILL.md`; without it the
skill can still be run by loading `SKILL.md` directly.

## File I/O
- **Claude Code / agentic environments:** reads the raw capture and any
  snapshot/existing JSON directly from the working directory or the
  conversation, writes the four required artifacts as real files (default:
  a `capture/` directory the user specifies, or the repo root).
- **claude.ai (no filesystem):** user pastes/uploads the raw capture (and
  optional snapshot); the four artifacts are returned as file attachments
  or delimited blocks per `adapters/generic.md`.

## Environment constraints
When run as an autonomous agent, follow `/shared/policies/AUTONOMY.md`: do
not ask "should I continue" mid-triage once given a clear `RUN_REQUEST`;
run the full procedure and stop only per `SKILL.md`'s stop conditions. Do
not ask the user to disambiguate every `AMBIGUITIES.md` entry before
finishing the run — surface them in the artifact and stop there; that is
completion, not a blocker requiring a mid-run question.

## Fallback
In a surface without a native Skill primitive (e.g. claude.ai without
filesystem access, or a harness that does not parse `SKILL.md` frontmatter),
load `SKILL.md` as a plain instruction document and follow
`adapters/generic.md` for artifact input/output.
